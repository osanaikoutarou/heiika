# 変換手順（skill の下書き）

文章・仕様・主張を、rikai 形式（JSON）に変換する。変換は**書き写し**であって、直しではない。

## 大原則
1. **判断を加えない。** 矛盾・間違い・穴があっても、そのまま写す。直したり、補ったり、解消したりしない。
2. **すべての要素に引用（quotes）を付ける。** 引用は元文の文字列をそのまま抜き出す（言い換えない）。複数箇所にまたがるなら複数書く。
3. **引用を付けられないものは analysis に入れる。** 元文に書いていない穴への気づき、矛盾の指摘、間違いの判定は、すべて analysis。
4. **言い換えない。** text や name は、なるべく元文の言葉をそのまま使う。用語の言い換えで意味が変わるのを避けるため。
5. **元文自体が曖昧・未決と言っているもの**（「必要なら」「未定」「要検討」など）は、body に unknown として写す（これは変換）。
6. **主張の大きさは「述語1つにつき1つ」。** 「A・B・Cを増やした」のような列挙は1つの主張にする（分けるのは分析や要旨の仕事）。
7. **省かれた主語は〔 〕で補ってよい。** 例: 「〔案Aは〕影響範囲が広い」。〔 〕の中だけが補った部分で、それ以外は言い換えない。
8. **まとまり・比較・選択肢の引用は目印の語だけにする**（「対応としては」「〜がありますが」など）。中身の文まで引用すると、主張の写し損ねを検証が見つけられなくなる（40字を超えると注意が出る）。
9. **評価（長所・短所など）は、評価対象のまとまりに入れる。** 元文で後ろにまとめて書かれていても同じ。位置は引用で分かる。
10. 下流（ブログ型の組み立て、点検）は、まとまりと主張だけに依存する。関係・状態・主張の種類は補助なので、迷ったら無理に決めず analysis にメモする。

## 形式（rikai/0.1）
```json
{
  "format": "rikai/0.1",
  "source": "元文そのまま",
  "meta": { "speaker": "人が与える前提情報（変換の対象外・検証しない）" },
  "imports":  [ { "id": "i1", "name": "トークン", "domain": "認証の基礎", "quotes": ["トークン"] } ],
  "states":   [ { "id": "s1", "name": "…", "desc": "…", "quotes": ["…"] } ],
  "versions": [ { "id": "v1", "name": "更新前", "quotes": ["更新前"] } ],
  "body": [ ノード, … ],
  "relations": [ { "id": "r1", "type": "理由", "from": ["n1"], "to": ["n2"], "quotes": ["ため"] } ],
  "senses":    [ { "term": "pending", "senses": [ { "meaning": "クーポンの適用予約", "ids": ["n3"] }, { "meaning": "サブスクの購入状態", "ids": ["n7"] } ] } ],
  "analysis":  [ { "id": "a1", "type": "穴", "about": ["n1"], "text": "症状が書かれていない" } ]
}
```

- **senses**（任意）: 同じ語が別の意味で使われているとき、語と意味ごとの要素 id を書く。
- **参照が曖昧なとき**: relations の from / to には、id の代わりに候補の配列を入れられる。例: `"to": [["n2", "n5"]]` は「n2 か n5 のどちらか（元文からは決められない）」。
- **言及**: 例として挙げただけの文（「〇〇さんが『〜』と言ったらしい」のような例文）は、claim に `"mention": true` を付ける。自分の主張ではない。

- **imports**: 元文が定義せずに使っている一般知識の語。読み手との差分はここで出す。domain は大まかな分野名。
- **states**: 時間や処理で変わる値。
- **versions**: 版や時点（修正前・修正後、更新前など）。元文に出てくるものだけ。

### ノード（body の中身）
すべてのノードに `id` `kind` `quotes` が必要。任意で `ctx`（version / env / scope / time / viewpoint / speaker）を付けられる。

| kind | 用途 | 必須の項目 |
|---|---|---|
| claim | 1つの主張 | text, type |
| seq | 時系列の手順 | steps（ノードの配列） |
| cond | 条件・場合分け。仮定なら hypothetical: true。ただし書きで他を上書きするなら overrides | when, then（ノードの配列）。else は任意 |
| group | ひとまとまり（名前で言及できる） | name, body |
| choice | 選択肢 | options（group の id の配列） |
| compare | 比べる | targets（id の配列）, axes（比べる観点の配列） |
| quote_of | 引用の入れ子（「◯◯さんが〜と言った」） | speaker, body |
| unknown | 元文自体が曖昧・未決と言っている箇所 | about |

### claim の type（元文の述べ方から決める）
| type | 目印の例 |
|---|---|
| 断定 | 「〜です」「〜する」と言い切っている（事実かどうかは判断しない） |
| 推測 | 「〜と考えられる」「〜だろう」「〜かもしれない」「〜と思う」（推量の意味のとき） |
| 伝聞 | 「〜らしい」「〜そうだ」「〜によると」 |
| 感想 | 「〜が良い」「〜が気になる」など話し手の評価（「〜と思う」が評価の意味のとき） |
| 規範 | 「〜すべき」「〜しなければならない」「〜してはいけない」 |
| 許可 | 「〜してよい」「〜でもよい」 |
| 定義 | 「AとはBである」「Aを B と呼ぶ」 |
| 提案 | 「〜する案」「〜してはどうか」 |
| 依頼 | 「〜してください」 |
| 質問 | 「〜か？」 |
| 決定 | 「〜とする」「〜方針とします」「〜ものとする」 |

### relations の type
理由（〜ため・〜ので）、結果（つまり・だから）、対比（〜一方で・〜が・ただし）、例、前提、並列（読点だけのつなぎで、因果か並列か決められないときの中立な関係）、言い換え（つまり・すなわち、で同じ内容を言い直すとき）。

## 手順
1. 元文を source にそのまま入れる。`python rikai.py init 元文.txt 出力.json` でひな形を作ると、書き写しの間違いが起きない。
2. 一般知識の語を imports に、変わる値を states に、版や時点を versions に拾う。
3. 主張・手順・条件・まとまり・選択肢を body に写す。入れ子はそのまま入れ子にする。
4. 「ため」「一方で」などの接続を relations に写す。
5. 元文に根拠のない気づきを analysis に書く。
6. `python rikai.py check <ファイル>` で検証する。「写していない箇所」が出たら、写し損ねがないか確認する。「注意」（長い引用、about のない要旨）も直す。
   - この形式で表しにくかったことは、meta.notes に書く。
7. `python rikai.py render <ファイル>` で人が読む形にする。


## 軽モード（mode: light）

構造化の重さの大半は、引用の書き写しと、まとまりの切り方の判断にある。組み直し（text-restructure）に使うのは「まとまり」と「主張」だけなので、それ以外を省いた軽い変換を用意した。

1. `python rikai.py init 元文.md 出力.json "話者" "読み手" --light` でひな形を作る。
   - 文に番号が振られる（`python rikai.py sentences 出力.json` で一覧）。
   - 見出し（# 行）と段落で、まとまり（group）が機械で先に作られる。見出しの下の段落は同じまとまり。見出しがなければ段落ごと。
2. 引用は文番号で書く。`"#12"`（文12全体）、`"#12-15"`（文12〜15）、`"#12:冒頭の語"`（文12の一部。冒頭の語は文12にある文字列）。文字列の引用も今までどおり使える。
3. 各まとまりの body に、主張（claim）・条件（cond）・手順（seq）・未確定（unknown）を写す。主張の text は元文の語のまま（言い換えない。主語は〔 〕で補ってよい）。1文に主張が2つあれば2つに分ける。
   - 機械が切ったまとまりが話題と合わないときだけ、分ける・まとめる（名前は短いタイトルにする）。
4. imports・states・versions・relations・senses は任意。書かなくてよい（必要なら書いてよい）。
5. `python rikai.py check 出力.json` で検証する。軽モードでは、まとまりの範囲引用は「写した割合」に数えない（主張の写し損ねが見えるように）。
6. 大原則（判断を加えない・引用を付ける・言い換えない）は同じ。
