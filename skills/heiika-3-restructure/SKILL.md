# 【3】構造を組み直す（heiika-3-restructure）

```bash
PY=$HEIIKA/.venv/bin/python
TOOL=$HEIIKA/tools
```

## 点数は2種類（混ぜない）
- **文の点数**: `scorer.py`。単語と、1文の中の係り受け。高いほど難しい。
- **つながりの点数**: `c_metrics.py`。(1) 文をまたいで前を指す言葉の数と距離（文字数）。(2) まとまりごとに初めて出る「読み手の知らない名前・名詞句」の数。高いほど読みにくい。
- 文を切ると、つなぎの言葉が増えてつながりの点数が上がることがある。2つは別々に直す。

## 手順
1. **構造化**: `heiika-structure` を「軽」モードで使い、構造（JSON）を出す。長い文章は見出しごとに分けて構造化する。
2. **文章にする** → `〈名前〉_3.md`
   - **まとまり（group）には見出しを付ける。** 読んで分かる短いタイトルにする（目安20字）。要約しない。中身を並べない。理由や補足を入れない。
   - **主張（claim など）には見出しを付けない。** まとまりの中の主張を、1つずつ段落にする。細切れになるなら、同じ話題の2〜4文を1段落にまとめてよい。
   - 主張が元の文の途中で切れているときは、文末だけ整えて1文にする。言い換えはしない。補った主語〔 〕は、括弧を外して文に入れる。
   - 主張の種類（断定・伝聞など）は表示しない。箇条書きは、場合分けや並列の選択肢など向く所だけに使う。本文全体を箇条書きにしない。
   - 文章全体のタイトルは、全体を表す短いタイトルにする（要約しない）。各セクションの最初の小見出しは、たいてい省略できる。
   - 上限（`scorer.SECTION_LIMIT`）を超えたセクションは `heiika-1-simplify` で下げる。
3. **つながりの点数を測る**: `$PY $TOOL/c_metrics.py 〈名前〉_3.md --detail`。「C の直し: 不要」なら 5 へ。
4. **つながりを直す**
   - 点の高い指示語（目安: 距離30字超、2文以上前）から順に、指す先の名詞に戻す。例: 「この条」→「第九条」、「その売買契約」→「撤回された売買契約」。指示語を外しても意味が変わらないなら外す。
   - 知らない語が無料枠（`new_free_items`）を大きく超えているまとまりは、話題ごとに分けて見出しを付ける。
   - 測り直し、文の点数が上がっていないことを確かめる。最大3回。
   - 機械の指す先の判定は誤認がある（「その他人」「この場合」が遠くに飛ぶ）ので、内訳の「指す語」をうのみにしない。
5. **意味を確かめる**: 元の文章の主張を1つずつ挙げ、残っているか、指す先を名詞に戻した所で意味がずれていないかを見る。

## 出力
組み直した文章（長ければファイルに書き出してパスを伝える）と、次の報告。
```
- 文の点数: 元 〇 → 〇。つながりの点数: 元 〇 → 〇（高いほど難しい）
- 見出し: 〇個。直した指示語: 「元」→「後」（〇か所）。分けたまとまり: 〇か所
- 意味の確認: 元の主張 〇個、すべて残っている（残っていない・ずれた可能性があれば、どれか）
```
