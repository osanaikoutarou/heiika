# 【5】仕様書風にする（heiika-5-spec）

読みやすさの点数は見ない。目的は、「何が条件で、何が例外か」を一つずつ確かめられる形にすること。

```bash
PY=$HEIIKA/.venv/bin/python
TOOL=$HEIIKA/tools
```

## 手順
1. **構造化**: `heiika-structure` で構造（JSON）を出す。関係（理由・対比・例外など）と条件（cond）を使うので、「軽」モードではなく通常の「変換のみ」モードで行う。
2. **まとまりごとに見出し**: `heiika-3-restructure` の手順2と同じ（短い名前、要約しない）。
3. **主張を1項目＝1仕様にする**: まとまりの中の要素を、階層化した箇条書きにする。
   - 1文に2つ以上のことがあれば分ける。
   - 用語は元のまま。言い換えない。情報を足さない。
   - 各項目の末尾に根拠を付ける: 元のどこか（条文なら「〔第1項〕」「〔第1項ただし書き〕」、文章なら「〔第2段落〕」など）。
4. **ラベルを付ける**: 構造（JSON）の関係と条件を、項目の頭に戻す。
   - `定義:` 「AとはBである」「AをBという」
   - `範囲:` 定義や決まりがどこまで及ぶか（「以下この条において」など）
   - `条件:` cond の when（「〜の場合」）。入れ子は入れ子のまま
   - `例外:` 上の項目を打ち消す条件（「ただし」「〜を除く」「この限りでない」）。何を打ち消すかを「上の『…』は」と明示する
   - `並列:` 同列の選択肢や列挙
   - `前提:` その項目が成り立つのに必要なこと
   - `決定:` 「〜とする」。`規範:` 「〜しなければならない」「〜できない」。`許可:` 「〜できる」
5. **確かめる**: 構造の主張・条件がすべて項目になっているか（`rikai.py check` の写した割合を参考に）。例外が、打ち消す先の直下に置かれているか。

## 出力
仕様書風の箇条書き（長ければファイルに書き出してパスを伝える）と、次の報告。
```
- 項目数: 〇（定義 〇、条件 〇、例外 〇 …）
- 元の主張 〇個、すべて項目になっている（なっていないものがあれば、どれか）
- 元の文章で2通りに読めた箇所（あれば）: 「…」 — どう読めるか
```
