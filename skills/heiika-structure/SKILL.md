# 【3】文章を構造化する（heiika-structure）

文章を rikai 形式の JSON に変換する。変換は**書き写し**であって直しではない。

## 入力
- 文章（貼り付け、またはファイル）
- モード: 「変換のみ」（既定）、「変換＋分析」、または「軽」（組み直し用。文番号の引用とまとまりの機械切りで、書き写しを減らす。`変換手順.md` の「軽モード」）
- 話者・読み手（任意）: meta に入れる

## 長い文章の扱い
- 目安3,000字を超える場合は、まず「重要な部分に絞るか」を聞く。構造化は重い作業（数百字でも数万トークン）なので、短く重要な説明に向く。
- 全体が必要なら、見出しごとに分けて順に変換し、見出しごとに別の JSON にする（結合はしない）。

## 手順

```bash
PY=$HEIIKA/.venv/bin/python
TOOL=$HEIIKA/tools
```

1. 変換の手順と形式を読む: `$TOOL/変換手順.md`（必ず読む。形式と大原則がここにある）
2. 元文をファイルにして、ひな形を作る（書き写しの間違いを防ぐ）:
   `$PY $TOOL/rikai.py init 元文.txt 出力.json "話者" "読み手"`
   「軽」モードなら末尾に `--light` を付け、`$PY $TOOL/rikai.py sentences 出力.json` で番号付きの文を見ながら、引用を「#12」「#12-15」「#12:冒頭の語」で書く。imports・states・versions・relations は省いてよい
3. 変換手順に従って、imports・states・versions・body・relations を埋める。
   - 判断を加えない。直さない。補わない（主語は〔 〕で補ってよい）
   - すべての要素に元文からの引用を付ける。引用は元文のまま
   - 引用を付けられない気づきは analysis に回す
   - 表しにくかったことは meta.notes に書く
4. 検証する: `$PY $TOOL/rikai.py check 出力.json`
   - エラーが0になるまで直す。「注意」も直す（長い引用など）
   - 「写していない箇所」が出たら、写し損ねがないか確かめる
5. 「変換＋分析」のときは、analysis に書く。種類は「穴」（書かれていない前提・症状・根拠など）、「矛盾」、「間違い」、「メモ」（曖昧さ、同じ語の別の意味など）。

## 出力先
- 入力がファイルなら、同じフォルダに `〈元の名前〉.rikai.json`。貼り付けなら scratchpad に置き、パスを伝える。
- 人が読む形: `$PY $TOOL/rikai.py render 出力.json`（プログラム風のテキスト）。

## 報告
```
## 構造化の結果
- 要素: 主張 〇、まとまり 〇、条件 〇、未確定 〇、関係 〇、分析 〇
- 検証: エラー 0、写した割合 〇%
- 表しにくかったこと: （notes の要約）
- 分析で見つかったこと（分析モードのとき、重要な順に3つまで）
- ファイル: 〈パス〉
```
続けて、render の出力を貼る（長ければ冒頭だけ）。
