# 【0】文章を点検する（heiika-check）

0番（準備）。文章の難しさを測る（1〜4の中でも使う採点）。あわせて、読み手が誤解しやすい箇所を点検する。書き換えはしない。

## 入力
- 文章（貼り付け、またはファイル）
- 読み手（任意）: 誰が読むか、何を知っているか。なければ下の「読み手の既定」。
- 既知語（任意）: 読み手が知っている専門用語。単語の点を0にする。

## 読み手の既定（ほかのスキルも、読み手の指定がなければこれを使う）
1. 指定があれば、それ。
2. なければ、**AI がこの会話や記憶で知っているユーザーの属性**（仕事、専門、経験年数、よく使う道具）に合わせる。ただし**少し簡単寄り**にする: 知っている分野でも、日常的に使う語だけ残し、たまにしか出ない語や、その分野の中でも専門性の高い語は言い換える（迷ったら言い換える側に倒す）。
3. ユーザーの属性が分からない分野は、**中高生〜大学生くらい**の知識とみなす（目的は「分かりやすく」なので、専門家向けには寄せない）。
4. 報告には、どう想定したかを1行で書く。

## 1. 採点する（機械）

```bash
PY=$HEIIKA/.venv/bin/python
TOOL=$HEIIKA/tools
$PY $TOOL/scorer.py --brief < 文章のファイル
```

- 貼り付けの文章は、一時ファイル（scratchpad など）に書いて標準入力で渡す。
- 既知語があれば、1行1語のファイルを作り `--known ファイル` を付ける。
- 点数は**高いほど難しい**。測っているのは文の形の難しさだけで、理解できるかは測らない。重みは仮の値で根拠がないので、目安としてだけ使う。
- 1回に読む塊の上限の目安は scorer.py の `SECTION_LIMIT`（今は105点）。

## 1b. 取りこぼした複合語を展開して加点する

既定で行う（LLM の判断を使う）。加点後の点数は、採点プログラムだけの点数より、難しさそのものに近い。

- **ほかのスキルの途中の採点**（heiika-1-simplify などの書き換えのたびの採点）では行わず、採点プログラムの点数だけを使う。手間と点数のぶれを増やさないため。加点は最後の報告のときだけ行う。

- **考え方**: 単語の点は、語の使われる頻度で測っている。見慣れない漢語（「狷介」など）にはもともと点が付くが、よく使う部品がつながった複合語（「無担保コールレート・オーバーナイト物」など）は、見慣れなくても単語の点がほぼ0になる（取りこぼし）。そこで、取りこぼした複合語だけを展開し、展開で増えた点を加える。単語の点で反応している語は展開しない（同じ難しさを二重に数えないため）。
- **読み手**: 指定がなければ、下の「読み手の既定」。

### 手順
1. 取りこぼしの候補を機械で出す: `$PY $TOOL/scorer.py --compounds < 文章のファイル`（名詞が続くまとまりのうち、丸ごとでは辞書になく、単語の点の合計が `COMPOUND_MAX_POINTS` 未満のもの。同じまとまりは最初の1回だけ）。
2. 候補のうち、読み手が知らないものだけを選ぶ。文脈から推測できるもの、人名は除く。
3. 選んだ語を、下の「展開の決まり」で展開する。
4. 加点する: 選んだ語を含む文ごとに、元の文と展開した文を採点し（1. と同じコマンド）、差（展開した文 − 元の文。プラスの分だけ）を足す。足した合計を「加点後の難しさ」とする。
5. 展開した文は採点のためのもの。読み手に見せるのは元の文章のまま。

### 報告に足すもの
```
- 加点後の難しさ: 見かけ 〇点 → 加点後 〇点（+〇点。高いほど難しい）
- 展開した複合語: 「元」→「展開」（+〇点）
```

## 展開の決まり

語や表現や知識を、**その語を知っている人がその語から受け取る中身を、ふつうの言葉で言い直したもの**に置き換える。展開の長さが、その語を見たときの「うわっ難しい」感の重さになるようにする。1b の加点と、heiika の「8 展開して」で使う。次の4つで確かめる。

1. **元の位置に置き換えられる**: 元の語があった場所にそのまま入れて、文が成り立つ（品詞・活用を合わせる）。本文の外に説明を足さない。元の語を残さない。読みを付けない。「〜とは〜ことだ」の枠を付けない。
2. **語が持っている要素は全部言う**: 熟語や複合語は、部品それぞれの意味を出す（「無担保コールレート・オーバーナイト物」→「銀行どうしが担保なしで1日だけお金を貸し借りするときの金利」、「博学才穎」→「学問が広く、才知が非常に優れている」）。上位の言葉1つにまとめない（「狷介」→「頑固」は足りない。「頑固で、人と合わせない」）。慣用句や比喩などの表現は、字面の部品ではなく、表している意味の要素を出す（「名を虎榜に連ね」→「役人の採用試験に受かり」）。
3. **語が持っていない情報は足さない**: 年代・数値・具体的な場所、歴史、理由や仕組み、使われ方、正式名称や原語の併記は入れない（「科挙」→「国の役人を選ぶための試験」。「隋から清まで…」は足しすぎ）。元の文が言っていないこと（推論・評価）も足さない。
4. **固有名詞は、最初に出てきたときだけ展開する**: 2回目からは元の名前のまま。人名は「李徴という人」程度に留める。地名・年号・組織名などは、「何の名前か」に位置づけを1つ足すまで（「隴西」→「唐の西の方の地方」、「天宝の末年」→「唐の天宝という年号の終わりごろ」、「FOMC」→「アメリカの金融政策を決める会合」）。

## 2. 点検する（判断）

文章を読み、次の6点を確かめる。本物の誤解は、文の長さより、ここで起きることが多い。

1. **数値**: 向き（高いほど良いのか悪いのか）と単位が書いてあるか
2. **同じ語**: 1つの語を2つ以上の意味で使っていないか。読み手が別の意味で知っている語を、断りなく使っていないか
3. **指示語**: 「これ・その・上記・このため」の指す先が、直前を読めば分かるか。段落や見出しの先頭にないか
4. **修飾**: 主張に、誰の見方か（話者）、いつの話か（時点・版）、どの場合か（条件）が付いているか。推測と断定が区別されているか
5. **前提**: 読み手が知らないと読めない語や前提がないか（読み手が分かっているときだけ）
6. **要は**: 文章全体（長い文章なら見出しや段落ごと）の「要は何か」を一文で言えるか。言えないなら、その理由（話題が複数ある、結論がない、など）

文章が長い場合（目安1,500字超）は、見出しや段落ごとに点検する。

## 3. 報告する

チャットに次の形で返す。見つからなかった項目は書かない。

```
## 点検結果
- 難しさ: 総量 〇点 → 加点後 〇点（高いほど難しい）／〇字・〇文。一番難しい文「…」〇点
- 要は: 「…」　（言えない場合: 言えない理由）

## 見つかったこと（重要な順）
1. 【種類】「該当箇所」 — 何が問題か。直し方の案（1行）

## 補足
- 読み手の想定: …
```

- 種類は「数値」「同じ語」「指示語」「修飾」「前提」「長い文」のどれか。
- 直した文章が欲しいと言われたら、heiika-1-simplify を使う。
