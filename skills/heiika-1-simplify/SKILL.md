# 【1】意味を変えずにやさしく書き換える（heiika-1-simplify）

## 入力
- 文章（貼り付け、またはファイル）
- 目標（任意）: 総量の点数（例: 105点以下）。なければ「限界まで」。
- 既知語（任意）: heiika-check と同じ。

## 使ってよい操作
- 文を切る（採点の「分割案」を参考にしてよい）
- 順番を変える（結論や依頼を先に）
- 並列のものを箇条書きにする
- 指示語を、指す先の名詞に戻す
- 「だから」「ただし」などの接続の言葉で、関係を明示する
- 省かれた主語や対象を補う（元の文から分かるものだけ）

## 使ってはいけない操作
- 用語の言い換え（意味が変わりやすい）
- 省略（情報が減る）
- 情報の追加（解説・例え）

これらが必要な場合は、そう報告して止まる（必要なら heiika-compress）。

## 手順
1. 採点する。

   ```bash
   PY=$HEIIKA/.venv/bin/python
   TOOL=$HEIIKA/tools
   $PY $TOOL/scorer.py --brief < 文章のファイル
   ```

   点数は**高いほど難しい**。貼り付けの文章は一時ファイルに書いて渡す。既知語があれば `--known ファイル`。
2. 点数の高い文から書き換える。内訳（長さ・単語・係り受け）を見て操作を選ぶ。単語の点が高いだけの文は、このスキルでは下げられないので触らない。
3. 書き換えた文章を採点し直す。
4. 目標に届くか、下がり方が小さくなる（前回から5%未満）まで、2〜3を繰り返す。最大3回。
5. 意味が変わっていないか確かめる。元の文章の主張を1つずつ挙げ、書き換え後にすべて残っているかを見る。話者・時点・条件、推測と断定の区別も残っているかを見る。

## 出力
書き換えた文章と、次の報告を返す。

```
## 書き換えの報告（点数は書かない。採点は書き換えの判断に内部で使うだけ）
- 使った操作: 文を切る（〇か所）、…
- 意味の確認: 元の主張 〇個、すべて残っている（残っていない場合は、どれか）
- 目標に届かなかった場合: 残った難しさの原因（専門用語が多い、情報量が多い、など）
```

- 入力がファイルなら、同じフォルダに `〈元の名前〉_やさしく.md` として書き出す。貼り付けならチャットに返す。
