# 【2】圧縮・調整する（heiika-compress）

意味が変わりうる操作も使って、文章を目標の難しさまで下げる。何を落とし、何を変えたかを必ず報告する。

## 入力
- 文章（貼り付け、またはファイル）
- **読み手**: 誰が、何を知っていて、読んで何をしたいか。指定がなければ heiika-check の「読み手の既定」（AI が知っているユーザーの属性に合わせ、分からない分野は中高生〜大学生くらい）。何を落とせるかは読み手で決まるので、省略を使うときに目的が分からなければ聞く。
- 目標（任意）: 総量の点数。なければ `SECTION_LIMIT`（今は105点。`ツール/scorer.py`）。
- 使ってよい操作（任意）: なければ全部。

## 操作（上から順に使う）
1. **意味を変えない書き換え**: heiika-1-simplify の操作（文を切る、順番、箇条書き、指示語を名詞に戻す、接続の明示）
2. **省略**: 読み手の目的にとって必要性の薄いものから落とす。
   - 話者・時点・条件・確度（推測か断定か）は、それが掛かっている主張と**一緒に残すか一緒に消す**。主張を残して修飾だけ落とすと誤解が起きる（例: 「他の参加者の見通し」を消して数字だけ残すと、本人の見通しに見える）。
3. **用語の言い換え**: 元の語の括弧での併記は控えめにする（多いと逆に読みにくい）。併記するのは、意味が変わりやすい重要な語と、読み方が分からないと読めない固有名詞だけ。目安は言い換えた語の2割以下。
4. **例え**: 使うなら「例えるなら」と明示する。例えで言い切った内容は、元文が言っていないことを含みうる。
5. **前提の先出し**: 読み手が知らない前提を、本題の前に短く置く。
6. **分割**: 1〜5で目標に届かないときだけ使う。各部分が目標以下になるように分け、各部分の頭に「要は」を一文で置く。

## 手順
1. 採点する。

   ```bash
   PY=$HEIIKA/.venv/bin/python
   TOOL=$HEIIKA/tools
   $PY $TOOL/scorer.py --brief < 文章のファイル
   ```

   点数は**高いほど難しい**。貼り付けの文章は一時ファイルに書いて渡す。読み手の既知語があれば `--known ファイル`。
2. 元の文章の主張を一覧にする（落としたものを後で報告するため）。
3. 操作を上から順に使い、そのつど採点し直す。目標に届いたら止める。
4. 一覧と見比べて、落としたもの・意味が変わった可能性のあるものを書き出す。
5. 修飾が外れた主張がないか確かめる。誰の発言か・推計か・いつの話か・どの場合か・「適切な」などの限定が消えて、主張だけが残っていたら、修飾を戻すか、主張ごと落とす。

## 出力
結果の文章（分割したなら部分ごと）と、次の報告を返す。

```
## 圧縮の報告（点数は書かない）
- 読み手: …
- 使った操作: 省略（〇か所）、言い換え（〇か所）、…
- 落としたもの: …
- 意味が変わった可能性のある箇所: 「元」→「後」 — どう変わりうるか
```

- 入力がファイルなら、同じフォルダに `〈元の名前〉_圧縮.md` として書き出す。貼り付けならチャットに返す。
